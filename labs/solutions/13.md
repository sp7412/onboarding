# Solution sketch: Lab 13

A strong solution keeps the facts contract explicit and makes every downstream consumer
state what confidence and evidence it requires.

## New fact type

1. Add the field to the JSON Schema with an allowed-value definition.
2. Add it to CallFacts and the extractor.
3. Add the permitted writer/consumer to the context policy.
4. Reject the fact when confidence is below the consumer floor or evidence is absent.
5. Add a test for both acceptance and rejection.
6. Add one trace field showing the evidence that justified the decision.

## Seeded contract violation

The intended failure is a consumer reading a proposed fact instead of the verified view.
Fix the consumer so it requests the minimum trust level it actually needs. Do not lower the
global floor to make the test pass.

## Acceptance evidence

The strongest capstone evidence is a trace showing:

extract -> validate -> bookability -> lead score -> dispatch -> commit -> claim guard

with the booking commit and spoken confirmation both grounded in application state.
